# 使用指南

安装见 [快速开始](../README.md#快速开始)，云端配置见 [部署指南](DEPLOYMENT.md)。本指南说明面板内的操作。

## 添加中转站、Key 与模型

1. 在「站点与模型」新建站点，填写名称、公网 HTTPS API URL、自己的 API Key 和分组。只允许公网域名与 HTTPS 标准端口。
2. 保存后进入添加模型窗口，选择 API 协议、希望验证的模型、实际请求模型名和默认档位。请求名必须是服务商接受的别名；可使用「获取模型」辅助填写。
3. 已有站点使用「添加同站模型」复用 URL 与 Key；使用「添加同站 Key」复用 URL 并新增另一条凭据。

一个 API URL 可保存多条独立 Key。界面将相同 URL 合并显示为一个中转站，各条 Key 配置可独立命名、分组并添加自己的模型。分组属于 URL + Key 配置，同一配置下的模型一起移动，其他 Key 不受影响。

「编辑中转站」可修改名称与 URL；修改 URL 需确认关联 Key 使用新地址。Key 配置、模型和监测计划也可独立编辑。已有任务与历史报告保留创建时的配置快照。

Claude 普通中转站默认使用类似 `claude-fable-5-1` 的连字符请求名；OpenRouter 默认使用 `anthropic/claude-fable-5.1`，可手动修改。模型列表只辅助配置，不证明服务商实际使用的模型身份。未收录模型可保存，但暂不支持判定。

保存完成后若列表刷新失败，面板会明确提示「已保存」及刷新问题，避免把刷新失败误认为配置未保存。此时重试刷新即可，无需重复新增同一模型。

## 删除中转站、Key 与模型

「站点与模型」页面和对应编辑窗口提供删除入口。先查看确认窗口中的范围、模型列表和监测数量，再确认删除。

| 操作 | 影响范围 |
| --- | --- |
| 删除中转站 | 同一 API URL 在所有分组下的 Key 配置及其模型，范围包含当前筛选外的关联配置 |
| 删除 Key | 仅该 Key 配置及其关联模型，同一中转站的其他 Key 保留 |
| 删除模型 | 仅该模型，同一 Key 下的其他模型和 Key 配置保留 |

相关监测计划和常用组合成员会移除，变为空的组合随之移除。删除的 Key 从保存的凭据中清除；历史报告、配置快照和已经取得的检测证据保留，可在「检测报告」中继续查看、导出，已删除目标会标注「已删除」。

有排队或运行中的检测时，需先停止并等待执行器确认结束，不能仅提交停止请求就立即删除。重复提交删除不会重复执行，旧编辑窗口也不能恢复已删除配置。确认期间关联 Key、模型或检测状态变化时，服务端会拒绝过期操作，请刷新后重新确认范围；不会只删除其中一部分。如需再次检测，重新添加配置。

## 发起检测

单目标检测使用目标默认档位；按分组或按中转站筛选后，「一键全部检测」仅执行当前范围，选择「全部」才覆盖全部目标。未收录模型会跳过并提示。

「勾选批量检测」支持任意选择或全选当前范围。排序保留勾选，切换分组、中转站或页面会清空勾选。应用不再设固定的目标保存数、勾选数或组合成员数上限，实际规模受平台存储与请求容量约束。

可以一次提交整个范围或任意组合。后台自动拆分为每批最多 **20 个目标**，本批并发检测，完成后自动启动下一批；各目标独立保存证据与错误，单目标失败不会取消其他目标。同一次选择的全部目标结束后只发送一封汇总邮件。批量编辑同样可选择超过 5 个目标。

整批总请求并发控制在 **64** 以内，按目标数量为每个模型分配 1–8 个请求工作槽，并共享原版内核的站点限流门；同站点收到 429 / Retry-After 时共同等待。模型采样数量、重试预算与评分算法保持原版。

云端 GitHub runner 可能排队；点击开始后先查看面板任务状态。重复提交会复用进行中的任务，避免重复预留额度。面板显示检测与邮件各自的进度。

预算对整次新选择原子预留，额度不足时不会只启动其中一部分。等待前面批次的任务不会因排队超过 30 分钟而误报失败；已经发起 GitHub 启动但未被领取的任务，才按自己的 30 分钟启动窗口超时处理。

## 暂停本次检测

- 进行中的目标卡片或报告中点击「停止本次」，只停止该目标的当前任务。
- 总览和站点页的「一键全部暂停」遵循当前分组 / 中转站筛选，与「一键全部检测」范围一致。
- 使用「勾选批量暂停」停止所选目标，其他范围的任务继续执行。

排队任务立即取消；正在运行的任务先显示「正在停止」，执行器确认并保存样本后显示「已暂停」。执行器每 3 秒检查停止请求，并使用原检测器的中止机制关闭传输、保留部分证据。

已经发出的请求仍计入用量；未知用量按预留上限保守结算。暂停后的匹配度只表示已完成的部分样本，不作为完整模型判定。再次检测会从头开始，不续跑旧样本；停止本次不修改后续定时监测计划。要长期停用自动监测，请关闭对应的监测开关。

## 常用检测组合

在总览中跨分组、跨中转站选择模型并命名，也可把当前勾选的模型保存成组合。各设备登录后可复用、编辑或删除组合。点击「检测组合」只执行组合成员，不受当前筛选影响，并使用模型最新的 Key 和默认档位。

组合只保存模型引用，保存或删除不会发起检测或影响模型、报告。组合区域默认收起，浏览器记住展开状态。手动邮件开启时，同一组合整批完成后发送一封汇总。

## 批量编辑与分组管理

「批量编辑」支持统一修改协议、希望验证的模型、实际请求名和手动默认档位。所有字段默认保持原值，保存前逐个预览变化。后端全部校验通过后原子更新；任一设置无效则全部不保存。编辑不发起检测、不消耗额度，监测档位与历史任务快照保留。

新建和管理分组集中在「站点与模型」。站点与模型窗口也可新建分组。删除分组后，其配置移回默认承接分组；模型、Key、监测计划与历史报告保留。默认分组可改名，不能删除。

总览与站点页支持按名称、检测结果、状态或最近检测时间排序，并记住当前设备的选择。排序不改变检测范围；新任务进行时仍参考最近一份已结束结果。

## 档位、预算与定时监测

GPT 快速 / 标准 / 深度分别为 32 / 64 / 128 次计划采样，Claude 为 48 / 72 / 120 次；还会预留约 50% 的请求重试预算。GPT 6.1 Sol 与 Astra 在小样本下区分可能不稳定，原作者推荐 128 次。

在设置中限制每日请求数与每月 runner 分钟。预算是任务预留与记录的控制，不替代模型账户账单或 GitHub 账单。间隔与每日监测使用单独的监测档位，不随手动默认档位的批量编辑而改变。

每轮到期的监测合并为一批，各目标保留自己的档位。历史报告记录协议、请求名、希望验证的模型、版本和 SHA-256，更新基准不会重写旧报告。

## 如何理解结果

| 结论 | 含义 |
| --- | --- |
| 支持申报模型 | 当前样本与所申报模型的行为指纹一致程度达到判定条件 |
| 强指向其他模型 | 现有证据达到指向其他候选模型的条件 |
| 证据不足 | 有效样本、差异或证据强度不足以给出明确结论 |

结合结论、有效样本数、匹配度、判定线、基准版本和错误信息解读。匹配百分比不是身份概率、降智百分比或服务可用率；检测不符本身不能判定服务商动机。不同基准或旧版分数不宜直接比较。

报告可在线查看错误摘要、HTTP 状态码、处理建议与完整 JSON，并导出。总览加载报告摘要；展开「预览完整报告（JSON）」或导出时，再读取完整样本与执行详情，以减少面板响应体和 Worker 处理开销。读取失败可点击「重新读取报告」重试，完整报告仍保存在数据库中。

摘要保留诊断出现的顺序与重复次数，不把多个相同错误展示成大量重复条目。连接检查或初始化失败也会保存阶段和原因。报告、在线错误、邮件和导出数据都经过凭据清洗。

## 邮件通知

在「设置 → 邮件通知」点击「使用 QQ 邮箱配置」，自动填写 `smtp.qq.com`、465（TLS）和当前账号 QQ 邮箱地址。QQ 邮箱应先开启 SMTP 服务并生成授权码；面板填写的是 **SMTP 授权码**，不是 QQ 登录密码或面板密码。

收件邮箱可与发件邮箱相同；支持多个收件人，以换行、逗号或分号分隔，重复地址会合并。收件人无需配置邮件服务器。

邮件默认关闭。开启后可选择：

- 异常与恢复：状态变化时发送该轮完整汇总。
- 每日汇总：北京时间 09:00 汇总自动监测；尚未结束的轮次等待完成。
- 每轮自动检测汇总：每轮自动任务结束后发送。

「手动检测也发送邮件」独立控制手动通知。开启时单目标发送摘要，勾选、分组、中转站或组合检测整批完成后发送一封汇总；关闭时只通知自动检测。关闭总开关后任何检测均不发信。测试邮件由按钮主动触发，不调用模型 API；云端通过 GitHub runner 发送。

同一次选择即使拆成多批，也在全部结束后发送一封汇总。混合批次中暂停的目标标为「已暂停，仅保留部分样本」，不会计为模型不符或请求失败。整次选择全部暂停时不发送即时结果邮件；自动异常比较忽略暂停轮次，下一份有效报告仍与上一份实际检测结果比较。

SMTP 授权码加密保存，不返回浏览器。只更换收件邮箱可沿用授权码；更换 SMTP 主机、端口或发件账号需重新填写。部分收件人被拒绝时可能已有邮箱收到，不自动重发。

汇总提供 HTML 表格与纯文本，按中转站 URL 分栏，列出模型、分组、档位、结论、匹配度、判定线、样本数、实际请求和私人报告链接。

## 常见问题

| 情况 | 处理方法 |
| --- | --- |
| 本地提示内核未就绪 | 运行 `npm run setup:local`；检查 Python 3.11+、网络和下载代理 |
| GitHub 下载失败 | 确认可访问 GitHub / raw.githubusercontent.com；必要时传入 `--proxy` |
| 本地代理使用虚拟 DNS | 启动器会检测系统代理或已验证的 TUN 路由；显式代理环境变量优先 |
| HTTP 404 | 检查 API 路径、协议和实际请求模型名 |
| HTTP 429 | 查看诊断，区分请求限流与账户额度不足 |
| HTTP 503 | 检查上游服务状态；明确限流信息才归类为限流 |
| 长时间排队 | 查看私人仓库 Actions 排队、启用状态与预算，及面板预留状态 |
| 部署检查提示占位符 | 先按部署指南运行 `npm run configure`，公开模板不能直接用于生产 |
| 已保存但列表未刷新 | 重试刷新列表，不重复新增同一模型 |
| 面板返回执行资源或服务错误 | 根据提示稍后重试；新版区分资源超限、网络中断、超时与上游返回的非 JSON 页面 |
| 删除被提示仍有任务运行 | 先停止检测，等待显示「已暂停」或任务结束后再删除 |
| 删除确认范围已变化 | 关闭旧窗口、刷新列表并重新确认影响范围 |
| 邮件发送失败 | 检查 SMTP 授权码、发件账号、TLS 端口、执行器与收件人是否被拒绝 |

本地只为子进程选择代理路径，不修改 macOS 网络设置。云端执行仍拒绝内网与虚拟 DNS 地址。
